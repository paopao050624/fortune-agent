# 紫微、占星、档案与塔罗体验

## 安装与启动

Python包要求3.10+，推荐3.11+（CI验证3.11/3.13）；Node.js 18+。紫微排盘桥已随Python包打包，不需要使用者安装npm依赖；占星和历法库可按可选依赖安装。

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[all]'
fortune-doctor
fortune-web --port 8766
```

模型解读需自行配置 `.env.example` 中的环境变量。离线排盘、档案、选牌与资料查看不需要API密钥。Node不在PATH时可用 `FORTUNE_NODE=/完整路径/node` 指定；不要把密钥写入代码或公开文件。

## 紫微斗数

```bash
fortune-chart ziwei --birth 2000-01-01T12:00:00+08:00 --gender female
```

固定 iztro 2.6.1、算法default。公历输入，仅支持中国标准时间+08:00；农历年界、闰月前半按本月后半按下月；23:00晚子时按次日，0:00早子时按当日。与八字午夜换日体系分开说明。分钟不改变时辰区间，未做真太阳时校正。

网页显示十二宫、命主身主、五行局、主辅杂曜、亮度、生年四化和大限年龄标签。空宫需结合对宫及三方四正，不能解释成没有该人生领域。男/女参数仅用于选定传统算法，不从姓名推测。

算法事实来自固定开源库，模型解释严格沿用计算结果。《紫微斗数全书》卷一已接入27条固定电子修订摘录，按实际星曜、四化与宫位匹配；程序校验模型引用ID并插入原文，见 [解释依据](ziwei-evidence.md)。尚未完成纸本全文校勘，不编造纸本页码，也不声称开源库等同该书所有版本的规则。当前提供本命盘，不提供紫微流日、飞化专题或多学派切换。

## 西方占星

```bash
fortune-chart astrology --birth 2000-01-01T12:00:00+00:00 --timezone Europe/London --latitude 51.4779 --longitude 0
```

Astronomy Engine 2.1.19（MIT），无需首次联网下载星历文件。十大天体、热带黄道、日期黄道坐标和地心视位置；宫制固定整宫制。上升星座为第一宫，MC单独显示，不拿MC直接当第十宫宫头。

出生时刻必须明确带UTC偏移并与IANA出生时区一致，包括夏令时。经纬度必须由用户提供，北/东为正、南/西为负；不按城市名偷偷猜测，不假填未知时刻。纬度±89.99度内可计算整宫，极区角点和出生时间敏感性须考虑。

相位包含合、六合、刑、拱、对冲；日月参与时容许度8度，其他6度。逆行按前后12小时黄经差观察。未包含凯龙、交点、小行星、Placidus或合盘；结果不证明占星解释的预测效力。

## 档案

“每日运势与回顾”可以创建、读取、编辑与切换多个代号，保存显示称呼、回答偏好、方法偏好、出生资料、IANA时区与经纬度。八字的中国标准时间出生字段与占星出生字段分开，海外占星资料不拿来偷偷改八字排盘。选择档案会同步对话、星盘和塔罗保存代号；具体方法仍由明确请求或页面选择。

模型仅在用户开启解读或发送对话时调用。保存工具历史需显式勾选“保存到档案”，不会默认存下每次星盘与塔罗问题。历史支持读取、JSON完整导出和恢复；导入同代号时拒绝覆盖，修改代号恢复时处理历史key冲突，避免丢失记录。导入记录标记为导入快照，不表示已重新计算或验证其事实。

删除档案同时删除它的日报、回顾与已保存工具历史；内存对话、独立每日塔罗旧缓存和已导出文件是独立记录。SQLite数据明文保存在本机，权限600；本地回顾不发送给模型。此版本是单人本机档案，不是带身份认证的多用户账户服务。

## 塔罗交互

支持每日一张、普通三张、选择对比、五张行动牌阵和十张凯尔特十字。用户先写具体问题，再洗牌、在78张背牌中按顺序选择、翻牌；服务端先固定牌序和正逆位，浏览器不会提前得到未选牌身份。

同一抽牌会话最多保留1小时，揭示后相同位置得到同一结果；改选需明确重新洗牌。牌阵变化会重建流程，问题变化会提示重新洗牌。追问使用原牌面，不重新抽牌；新牌阵的牌位是项目约定，其中未来方向仍作为反思而非保证。

牌背、布局与翻牌动画由原生HTML/CSS绘制；78张正面为项目原创符号SVG插画，MIT授权，不是Waite原版图像或原文释义。逆位旋转牌面，名称和牌位仍正向可读，不含授权不清的商业牌图。原文仍使用已有Waite资料，缺少核对牌义的方向明确说明。选牌位置可用数字输入以便键盘操作，背牌按钮有可访问名称与选中状态。

## Docker本机部署

```bash
docker compose up --build -d
# 浏览器打开 http://127.0.0.1:8766/
docker compose logs -f
```

Compose只发布至本机127.0.0.1；容器内部显式绑定0.0.0.0，保持Host与请求token校验。名为fortune-data的卷保存档案和历史；`docker compose down`保留卷，`docker compose down -v`会删除数据，不应在需要保留档案时执行。默认不是公网网站。

本机Docker守护进程若未运行，需先启动Docker Desktop。GitHub CI提供Docker构建和离线HTTP流程检查。开源交付材料包括许可证、第三方完整许可通知、贡献指南、安全说明、问题模板、固定依赖、测试与构建流程；只有实际通过CI的提交才称为发布验证通过。

若把容器8766映射到不同宿主机端口，须显式传入 `fortune-web --bind 0.0.0.0 --port 8766 --external-port 18766` 并使用 `-p 127.0.0.1:18766:8766`。服务器仅额外接受该端口的本机Host，不开放任意域名。
