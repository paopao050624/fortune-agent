# 周易原文库与解读规则

本模块现在包括完整的目标经文集、版本化取辞、结构化模型解读和离线参考查阅。完整范围为 64 卦卦辞、384 条爻辞以及乾的用九、坤的用六；不包含彖传、象传、文言、现代译注或所有占筮流派。

## 原文来源与整理

来源为 Wikisource 的 `周易/<卦名>` 页面。每卦保存修订 ID、时间戳、固定链接和原始 wikitext SHA-256。只提取页面蓝色“易经”经文区，停止于彖、象等解释部分。库为 `src/fortune_agent/data/iching_texts.json`，卦序组合表单独保存在 `iching_hexagrams.json`。

这是电子转录，不是已选定纸本的完整校勘本，不能编造纸本页码。转录主字、句读保留；`{{另}}` 的主字用于正文，其他读法和脚注另存 `notes`。艮卦原页缺少 HTML 闭合标签，按经文列表边界解析并记录格式说明；否卦爻题的逗号也保留。库中的异文和“吉、凶”等历史表达不能当作现实风险概率。

原文是历史经文，程序与数据说明仍保存来源归属；没有引入付费现代译注。更换底本或异文选择时，需要更新记录、重新校验并另建评估结果。

## 默认规则：moving-count-v1

这是本项目明确采用的取辞约定，借鉴常见的按动爻数量取辞形式。当前没有把它确证为某一古籍中逐字一致的规定，也不称其为所有流派唯一方法。

| 动爻数 | 选择的经文 | 主次 |
| --- | --- | --- |
| 0 | 主卦卦辞 | 主辞 |
| 1 | 主卦该动爻的爻辞 | 主辞 |
| 2 | 主卦两条动爻辞 | 较高爻位为主，另一条为辅 |
| 3 | 主卦卦辞与变卦卦辞 | 并列，不强定单一主辞 |
| 4 | 变卦中两个未动位置的爻辞 | 较低爻位为主，另一条为辅 |
| 5 | 变卦中唯一未动位置的爻辞 | 主辞 |
| 6 | 一般选变卦卦辞；主卦乾、坤分别选用九、用六 | 主辞 |

“未动位置”始终以本次六爻动静记录确定，爻辞的阴阳标签则来自选用的主卦或变卦经文。程序不会把“主辞”解释为结果必然发生，也不会按模型偏好事后改换规则。

## 比较规则：all-moving-v1

始终展示主卦卦辞；有动爻时，另列主卦全部动爻辞与变卦卦辞。乾坤六爻全动时还列用九或用六。所有条目并列，不作主次排序。这是项目用于比较的读法，不冒称另一个权威流派。

可以在网页或 CLI 选择规则，结果保存所用策略、解释、具体条目 ID 与参考库哈希。两种规则都经过全部 `4^6 = 4096` 种六爻输入测试。

## 模型解读

程序先计算卦象并选文，再发送具体问题、规则、原文、异文和定位。模型用结构化 JSON 返回总结、每个条目的传统含义与现代应用、行动建议、限制；`passage_id` 必须严格匹配程序提供的 ID。未提供、重复或遗漏的条目会使解读失败，不把这类回答交给用户。

引用的原字和链接由程序追加，不让模型生成引用原文。模型解释仍可能有语义错误，ID 校验只能保证引用对象正确，不能证明解释或预测可靠。真实案例需要人工复核；医疗、法律、投资等问题不能以历史占辞替代专业判断。

## 使用

```bash
# 查看取辞和完整依据，不需要 API
fortune-iching --lines 9 7 7 7 7 7
fortune-iching --lines 9 8 7 6 7 8 --policy all-moving-v1

# 查看某卦的全部卦辞、爻辞和特殊辞
fortune-iching --reference 1
fortune-iching --reference 64 --json

# 配置中转站环境变量后解读，不重掷硬币
fortune-iching --lines 9 7 7 7 7 7 --interpret '研究项目该怎么推进？'
```

网页有全文参考库下拉选项、两种规则、所选原文及模型解读。起卦记录和问题不会本地缓存；API 请求会发送到你配置的中转站。单独查阅参考库无需模型配置。

## 重建与评估

```bash
python scripts/fetch_iching_texts.py
python scripts/build_iching_texts.py
python -m fortune_agent.iching_eval_runner \
  --output work/iching-evaluation.jsonl --timeout 90
```

原始下载保存在忽略目录 `work/`。已有发布库时，抓取脚本按每卦固定修订号重取，不静默升级到新版本；构建脚本检查 64、384、2 的数量、爻位、阴阳和格式。评估中断后用 `--resume`，模型、问题、规则、提示词和资料哈希必须与旧记录一致。

固定评估案例涵盖零至六动爻、乾坤特殊辞、并读策略、敏感问题和引用边界。自动校验是人工评分的前置检查，不以通过 JSON 校验宣称全部语义正确。
